# MatonOS Shell — Expo CNG architecture

MatonOS Shell is an updateable Expo HOME app using SDK 57, its compatible React Native 0.86 release, New Architecture and Hermes. `android/` is generated by Expo Continuous Native Generation, ignored by git and never hand-edited. Local Expo modules hold native Android functionality: Home/Recents activities, the persistent shelf overlay service and Java fallback, app/task/wallpaper operations, and BootReceiver. Config plugins own manifest wiring, bridge/overlay permissions, HOME routing, x86_64 ABI filtering, signing, and generated privileged-permission metadata.

The shared `apps/rn-common` package provides the dynamic Material 3 theme, components, hooks, API typings and a Kotlin Expo module that delegates all bridge work to buildinfra's shared Java `MatonosClient`. It does not fork or reimplement that client. Settings will consume the same package and pin the same Expo/RN/Hermes/toolkit versions.

Expo UI with Jetpack Compose is the target UI kit. A real Compose Switch rendered inside `Host` is included on Home as a build/runtime smoke path. React Native Paper remains installed during migration and should be treated as transitional. The root configuration keeps Hermes enabled and restricts packaged native ABIs to x86_64; release bundling embeds Hermes-compiled JS bytecode, while the development client may use Metro.

Home displays the wallpaper through a transparent native window. The shared shelf service owns overlay type, authorization, insets/z-order, compact/expanded sizing and survival across app launches. React Native supplies the shelf contents and all app-facing screens. The app drawer remains a searchable icon grid; Recents uses the narrowly authorized System Bridge for task switching, closing and fullscreen actions. If React Home fails during startup, the native module displays a searchable Java app grid; the shelf has its own Java fallback. Desktop freeform window ownership remains with WM Shell.

Java activities/services are the native lifecycle boundary, not the UI toolkit. Keep JS in `src/screens`, `src/components`, and `src/App.tsx`; shared UI and client API stay in `../rn-common`. Keep TypeScript strict, pinned and compatible with Hermes bytecode compilation: no generated source evaluation or runtime Metro dependency in production.
