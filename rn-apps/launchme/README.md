# MatonOS Shell — Expo UI project

MatonOS Shell owns fullscreen Home and the App drawer, registered as separate React roots (`MatonHome`, `MatonDrawer`). Task Recents is a separate Expo app in `../recents` (`org.matonos.recents`) with its own AppCompatActivity anchor and React surface. The persistent shelf is a third app in `../shelf` (`org.matonos.shelf`) with its overlay service, RN surface, boot receiver and Java fallback. Shelf opens Drawer through Shell's `DrawerActivity`, opens Recents through the Recents app, and opens Home through the HOME intent.

This is a standard Expo SDK 57 project (React Native 0.86.3, Hermes, New Architecture). Native Android project files are generated by `npx expo prebuild --platform android --clean`; `android/` is ignored and must not be edited or committed. Native shell/service glue lives in `modules/matonos-shell`, and the shared MatonOS bridge client adapter lives in `../rn-common` as an Expo module. The Settings app can reuse `rn-common` and should pin the same Expo/RN/Hermes versions.

## Fast Refresh on the windowed MatonOS VM

From this directory, run one command:

```bash
./dev.sh
```

The script uses `127.0.0.1:5555` only, verifies the local development key, runs `npm ci`, regenerates Android with Expo prebuild, builds and installs an Expo dev-client APK signed with Shell's app-specific key, starts Metro on port 8081 and opens Home. Run `../shelf/dev.sh` for the shelf on 8082 and `../recents/dev.sh` for Recents on 8083. Each app has its own signing key and `--reset` restores only that app's image APK.

Open this folder in VS Code and install the recommended extensions. Press F5 with **Attach to MatonOS Shell (Hermes)** selected to attach React Native Tools directly to Hermes. The in-app developer menu is also available with `adb -s 127.0.0.1:5555 shell input keyevent 82`.

The script expects the windowed user VM to be running and intentionally fails rather than connecting to another device. Environment overrides: `ADB`, `MATON_ADB_DEVICE`, `MATON_ANDROID_SDK`, and `MATON_KEY_DIR`.

Expo generates the native Android project; local Expo modules own Home and Drawer activities plus app operations. The Recents app owns its task UI and AppCompat anchor. Shelf owns overlay window behavior and its Java fallback. Each package has its own ReactHost/Hermes process. Keep native UI libraries such as `react-native-safe-area-context` as direct pinned dependencies; the release linkage check verifies their packages and Fabric view code reach the APK.

## Change the UI

- `src/screens` contains page-sized UI, `src/components` reusable UI, and `src/HomeApp.tsx` / `src/DrawerApp.tsx` are the registered Shell roots. Recents UI is in `../recents/src/screens/RecentsScreen.tsx`; shelf UI is in `../shelf/src/components/Shelf.tsx`. Keep screen and native contracts typed and avoid dynamic code generation, `eval`, `Function`, `with`, and Proxy-based state libraries for Static Hermes compatibility.
- `../rn-common` (`apps/rn-common`) contains the reusable MD3 dynamic-color theme, common components/API surface, and typed `MatonOS` Expo module wrapper. Its Kotlin adapter delegates to `buildinfra/client`; do not duplicate that client in an app. Pin Expo, React, RN, Hermes, Paper and Material Color Utilities together when adding Settings.
- Shell native APIs are in `src/MatonShellNative.ts` and `modules/matonos-shell`; bridge calls/events and shared hooks are in `../rn-common`. Recents tasks, switching, closing and thumbnails use that typed wrapper. Shelf UI and Java fallback are in `../shelf/src` and `../shelf/modules/matonos-shelf`.

## Using Expo UI (Jetpack Compose)

`@expo/ui` is the target UI kit; React Native Paper remains during migration. The development app drawer includes a Compose `Switch` inside a `Host` so you can check the Android rendering path without placing a demo control on the production Home screen:

```tsx
import {Host, Switch} from '@expo/ui/jetpack-compose';

<Host style={{width: 64, height: 48}} colorScheme="dark">
  <Switch value={enabled} onCheckedChange={setEnabled} />
</Host>
```

Use Compose components only inside `Host`. Paper and Compose views can be mixed in the same React Native tree; keep explicit host sizing for controls. `@expo/ui`'s Android module applies the Kotlin Compose compiler plugin and pins its Compose dependencies. Expo SDK 57 is used because it is the stable SDK line matching the selected React Native 0.86 release; check its compatibility table before upgrading.

## Metro hot reload

The Shell UI loop is `./dev.sh` on Metro 8081. Shelf uses 8082 and Recents 8083. Production/release builds embed the JS bundle and compile it with Hermes; they do not contact Metro and do not include JSC. Each `dev.sh --reset` restores that package's image APK.

After release builds, run `npm run check:release-linkage` in each project. After a fresh image boot, run `scripts/smoke-split.sh <adb-serial> <evidence-directory>` to capture Home, Drawer, Recents and Settings with Shelf visible, collect all three process memory reports, and fail on Shell/Shelf/Recents crashes or the Expo AppCompat lifecycle error. It leaves Settings open for visual inspection.

Dependencies are pinned in `package.json` and `package-lock.json` (Node 22/npm 9). Run `npm ci`, `npx expo prebuild --platform android --clean --no-install`, `npm run typecheck`, `npm run lint`, and `npm run format:check` to check the project. Image APKs are built and signed by `tools/build-apps.sh`; the required CNG build-helper changes are listed in `SHARED-CHANGES.md`.
