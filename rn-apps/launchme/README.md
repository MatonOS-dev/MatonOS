# MatonOS Shell — Expo UI project

This is a standard Expo SDK 57 project (React Native 0.86.3, Hermes, New Architecture). Native Android project files are generated by `npx expo prebuild --platform android --clean`; `android/` is ignored and must not be edited or committed. Native shell/service glue lives in `modules/matonos-shell`, and the shared MatonOS bridge client adapter lives in `../rn-common` as an Expo module. The Settings app can reuse `rn-common` and should pin the same Expo/RN/Hermes versions.

## Fast Refresh on the windowed MatonOS VM

From this directory, run one command:

```bash
./dev.sh
```

The script uses `127.0.0.1:5555` only, verifies the local development key, runs `npm ci`, regenerates Android with Expo prebuild, builds and installs an Expo dev-client APK signed with the same `07522fac…` certificate as the image app, starts Expo Metro, forwards port 8081, selects MatonOS Shell as HOME, and opens Home. Saving a `.tsx` file should Fast Refresh Home, drawer, recents, and the shelf surface; timing still needs verification on the live VM. To restore the image's Hermes-bytecode APK and remove the update, run `./dev.sh --reset`.

Open this folder in VS Code and install the recommended extensions. Press F5 with **Attach to MatonOS Shell (Hermes)** selected to attach React Native Tools directly to Hermes. The in-app developer menu is also available with `adb -s 127.0.0.1:5555 shell input keyevent 82`.

The script expects the windowed user VM to be running and intentionally fails rather than connecting to another device. Environment overrides: `ADB`, `MATON_ADB_DEVICE`, `MATON_ANDROID_SDK`, and `MATON_KEY_DIR`.

Expo generates the native Android project; local Expo modules own Home intent routing, the shelf overlay service/window, bridge-backed task operations, and the Java Home/shelf safety fallbacks. React Native renders Home, drawer, recents, and shelf surfaces through the shared ReactHost. Keep native UI libraries such as `react-native-safe-area-context` as direct pinned dependencies; the release linkage check verifies that their packages and Fabric view code reach the APK.

## Change the UI

- `src/screens` is intended for page-sized UI, `src/components` for reusable UI, and `src/App.tsx` is the current screen composition entry point. Keep screen and native contracts typed; avoid dynamic code generation, `eval`, `Function`, `with`, and Proxy-based state libraries so a future Static Hermes build remains possible.
- `../rn-common` (`apps/rn-common`) contains the reusable MD3 dynamic-color theme, common components/API surface, and typed `MatonOS` Expo module wrapper. Its Kotlin adapter delegates to `buildinfra/client`; do not duplicate that client in an app. Pin Expo, React, RN, Hermes, Paper and Material Color Utilities together when adding Settings.
- Shell native APIs are in `src/MatonShellNative.ts` and `modules/matonos-shell`; MatonOS bridge calls/events and hooks are in `../rn-common/src/MatonOS.ts` and `src/hooks`.

## Using Expo UI (Jetpack Compose)

`@expo/ui` is the target UI kit; React Native Paper remains during migration. The Home screen includes a small real Compose `Switch` inside a `Host` so the Android rendering path is exercised:

```tsx
import {Host, Switch} from '@expo/ui/jetpack-compose';

<Host style={{width: 64, height: 48}} colorScheme="dark">
  <Switch value={enabled} onCheckedChange={setEnabled} />
</Host>
```

Use Compose components only inside `Host`. Paper and Compose views can be mixed in the same React Native tree; keep explicit host sizing for controls. `@expo/ui`'s Android module applies the Kotlin Compose compiler plugin and pins its Compose dependencies. Expo SDK 57 is used because it is the stable SDK line matching the selected React Native 0.86 release; check its compatibility table before upgrading.

## Metro hot reload

The normal UI loop is `./dev.sh` above. For manual development, run `npx expo start --dev-client` and forward `tcp:8081` with adb. The Metro dev menu remains available through the Menu key event. Production/release builds embed the JS bundle and compile it with Hermes; they do not contact Metro and do not include JSC. `dev.sh --reset` restores the image APK.

After a release build, run `npm run check:release-linkage` to verify the generated autolinking metadata and APK include required native view managers. After the coordinator provides a fresh image and boots it, run `scripts/smoke-image.sh <adb-serial> <evidence-directory>` to capture HOME, verify the Home activity, and fail if the crash buffer contains shell errors.

Dependencies are pinned in `package.json` and `package-lock.json` (Node 22/npm 9). Run `npm ci`, `npx expo prebuild --platform android --clean --no-install`, `npm run typecheck`, `npm run lint`, and `npm run format:check` to check the project. Image APKs are built and signed by `tools/build-apps.sh`; the required CNG build-helper changes are listed in `SHARED-CHANGES.md`.
