## Headline

**Linux layer v3 works end to end on an enforcing image.** Extreme Tux Racer installs from
Flathub, launches from its stub icon and renders its menu, **GPU-accelerated**. This ran on a
clean image built from `main`, with nothing patched on the VM.

The whole chain runs inside the stub app's own UID and `untrusted_app` domain, under Android's
real app seccomp filter: stub → `libmatonos-v3-loader.so` → bionic `flatpak run` → bwrap
(virtual) → `etr`. The stub also runs its own compositor and Xwayland. Nothing privileged takes
part in a launch.

GPU evidence: Mesa logs "Using DRI3 for screen 0"; the game has `/dev/dri/renderD128` open and
mapped; `libgallium-26.2.4` comes from the GL.default extension; there are no llvmpipe threads.

## Decisions today (user) — details in memory `compat-proxy`, `installer-staging-flow`, `no-v2-fixes`

- **Rule: don't fix v2 bugs that v3 retires.** v2 is fully gone (none of it works on
  enforcing). If a test fails in retired code, bring the replacement forward instead.
- **The compositor lives in the stub.** There is no global compositor; the leftover
  coordinator is deleted.
- **linuxd = install, update, store, runtime refcount, remotes, metadata.** It has no runtime
  role. `prepareRuntime` moved into the stub. Next: the launch spec becomes the stub running
  `flatpak info` itself.
- **DNS:** the forwarder stays (netd path: Private DNS, VPN, DNS64). It is hosted in the stub on
  an unprivileged port.
- **Downloads:** the v2 fd grant is dropped; the SAF folder-grant plan is fine.
- **Portals:** Flatpak's own portal, run per app under the proxy, on the app's bus.
- **Hard links:** emulated with symlinks and an inode store (done).
- **Store API (round 12, not started):**
  - Calls: `install_app(id, repo)` inline; `install_repo(.flatpakrepo)` with a system prompt
    (shows the fingerprint, unsigned repos refused); `update_check`; `update_app`;
    `uninstall_app` (admin-only "all users" flag); `remove_repo` (prompt, uninstalls that repo's
    apps).
  - Callers need a signature-protected permission.
  - **Remotes are system-wide.** An app is pinned to its remote; the same id from another
    remote is refused.
  - User restrictions: `DISALLOW_INSTALL_APPS`/`DISALLOW_UNINSTALL_APPS`; repo add/remove is
    admin-only and blocked by `DISALLOW_INSTALL_UNKNOWN_SOURCES_GLOBALLY`.
  - Flow: store → linuxd; linuxd's sandboxed installer (`AID_VENDOR_MATONOS_FPINSTALL`, bionic
    Flatpak, netd DNS) pulls; linuxd verifies (its own keyring) and deploys; the bridge installs
    the final stub **once** (no early stub, no refresh race).
- **Controllers:** Android input → virtual evdev device in the proxy, plus extended Android
  support (kernel HID drivers, `.kl`/`.idc`, upstream key maps).
  - Raw USB (USB Host API): low priority, after v1. Raw BT HID: maybe.
  - Device broker / udev idea: parked.
- **SysV IPC is next to emulate, after these fixes.** Reuse the core semantics in
  `git show 0b5bb33^:linux/sysvipc/`; the transport moves into the proxy (shared mapping, futex).
- **GPU acceleration is a core feature.**

## How to test fast (learned today)

- **Builds:** `MATON_BUILD_COORDINATOR=1 tools/build.sh -K -M -j 16` takes 15–45 min. A module
  only: `-m matonos-linuxd`. Host APK only: `MATON_APPS_FORCE=1 MATON_APPS_ONLY=matonos-wayland-host
  tools/build-apps.sh`. wlroots/compositor libs: `linux/compositor/build-compositor.sh`;
  Xwayland: `build-xwayland.sh`, then copy `out/matonos/compositor/xstage/x86_64/bin/Xwayland`
  into `linux/compositor/prebuilt/system_ext/bin/`. The loader: `linux/compat-proxy/build-android.sh`;
  host tests: `tests/run.sh` (from a clean `build/`).
- **Hot-patching the VM without an image build (verity can't be disabled on the live image):**
  - linuxd (an init service): bind-mount from a tmpfs that is NOT `nosuid` (SELinux denies
    domain transitions from `/data`), with `chcon u:object_r:matonos_linuxd_exec:s0`, then
    `stop`/`start matonos-linuxd`.
  - Loader, host APK, Xwayland (loaded by apps): bind **inside Zygote's mount namespace**:
    `nsenter -t $(pidof zygote64) -m -- /system/bin/sh -c "...mount --bind..."` (toybox needs
    `--`). Copy to a new file name each time, or it fails with "Text file busy".
  - After restarting linuxd, wait a moment: the bridge re-registers its identity callback
    (fixed in `77945aa` via linkToDeath).
- **Quick denial sweep:** `setenforce 0` WITHOUT a Zygote restart keeps the app seccomp filter
  active.
- **logcat:** `adb logcat -G 16M`, or the 256K ring loses linuxd lines. Stream to a file during
  installs.
- **Proxy trace:** `touch /data/data/<stub>/cache/v3-trace` as root. Debug Mesa through a Flatpak
  override in `$(readlink -f /data/linux-app/install/<appid>)/overrides/<app-id>`
  (`[Environment] LIBGL_DEBUG=verbose`), then remove it.
- **Never use `pkill -f`** (it killed my own shell). Use `out/pc-logs/agents/vm.sh` or literal PIDs.
