## What was wrong and what changed

### X11 for Flatpak apps (MC launcher, Brave, any Chromium/CEF/Electron)
Root causes found, in order:
1. flatpak-run.c (L285-312) mounts `--tmpfs /tmp/.X11-unix` and **unsets
   DISPLAY** unless the host DISPLAY is `:N` with a host socket. We passed a
   path → sandbox had no DISPLAY.
2. The sandbox runs as `system` (under linuxd); X sockets were `u0_a87 0600`.
   The old per-app `chown` from the compositor app UID could never succeed —
   **the "per-app X11 isolation works" claim in the Oct 2 handover was false**.
3. The carried wlroots patch left `x_fd[0] = -1` (no abstract socket) but
   `exec_xwayland` still cleared CLOEXEC on it → **Xwayland never started on
   any image up to r15**.
4. r16: Xwayland exec'd but `libpixman-1.so` / `libwayland-client.so` only
   lived inside the compositor APK → linker failure.

Design now (6bc2224, by codex + opencode, reviewed/fixed by coordinator):
- Compositor: Xwayland sockets in its private `files/x11` (0711 dir, 0666
  sockets — same pattern as Wayland). Bridge delegates that dir fd + name
  `X<n>` to linuxd (AIDL changed in ISystemBridge + both ILinuxd copies).
- linuxd relays X11 exactly like Wayland (SCM_RIGHTS) from
  `/data/matonos/linux/runtime/wayland-<N>-x11`. No DISPLAY exported. If the
  X socket is missing it launches Wayland-only and logs a warning (2a774e0).
- `matonos-bwrap` (linux/flatpak/matonos-bwrap.c, Soong, system_ext) is
  FLATPAK_BWRAP when the relay socket exists. flatpak execs bwrap with an
  EMPTY env and bundles the env as `--setenv` in the `--args` fd; the shim
  reads it from there, and **only for sandboxes carrying flatpak's
  `--tmpfs /tmp/.X11-unix`** (so the xdg-dbus-proxy sandbox is untouched)
  inserts `--bind <relay> /tmp/.X11-unix/X0 --setenv DISPLAY :0` after the
  `--args` pair. Host test: `linux/flatpak/tests/bwrap_test.c`.
- Host `/tmp` is never touched (user: host /tmp/.X11-unix breaks Brave).
- Shared `/data/matonos/linux/x11` (1777), its label and rules removed.
- Xwayland libs: `tools/stage-xwayland.sh` now also stages pixman +
  wayland-client from the compositor build (88d175b).

### Brave: `bwrap: Can't mkdir /tmp/.X11-unix: Permission denied`
AOSP `system/core/rootdir/init.rc:108` mounts a shell-owned 0771 `/tmp`.
Brave's manifest has `filesystems=/tmp`, so it was bound in and bwrap (system)
could not create flatpak's mount point. linuxd now applies
`flatpak override --system --nofilesystem=/tmp` once (88d175b) → every
sandbox gets a private /tmp.

### Firefox (user report on r15/r16)
- Double header / own window buttons: linuxd writes
  `gtk-decoration-layout=:` into the sandbox gtk-3.0/gtk-4.0 settings.ini
  (verified written on r16) — **but GTK ignores settings.ini when a settings
  portal answers**, and our broker's portal does. 430b811 makes the broker
  portal (`linux/dbus-broker/portals.c`) return
  `org.gnome.desktop.wm.preferences button-layout=":"`; broker binary rebuilt
  with `linux/dbus-broker/build-android.sh` and installed into
  `linux/flatpak/prebuilt/system_ext/bin/`. Any future real portal must keep
  reporting this.
- Rounded corners: toplevels are configured tiled (all edges) **and**
  maximized (Firefox ignores tiled). X11 surfaces: maximized via xwm.
- Popup menus closing on hover: pointer enter moved keyboard focus to the
  popup surface → toplevel focus-out → GTK dismissed the menu. Keyboard focus
  now stays on the window root surface (f26930d).
- MatonWLR log levels fixed (SILENT<ERROR<INFO<DEBUG).
