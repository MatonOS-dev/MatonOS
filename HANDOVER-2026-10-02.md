## Confirmed failures and fixes in current source

### Compositor abort

Tombstone captured from r6:

```text
org.matonos.compositor:compositor — SIGABRT
wlr_xdg_surface_schedule_configure: assertion "surface->initialized" failed
```

Our `linux/compositor/native/compositor_core.c` configured new toplevels
and popups before their initial surface commit. Current source follows the
checked-out wlroots 0.20.2 lifecycle: configure on initial surface commit,
guard resize with `initialized`, and remove commit listeners on destruction.
Host APK compilation succeeded; runtime behavior is not confirmed.

`MainActivity.java` now logs launch exceptions and explains a dead compositor
instead of displaying `Cannot start application: null`.

### Adaptive icons fall back to the Android placeholder

A guest `app_process` diagnostic established the precise failure:

- `ActivityInfo.icon` and `ApplicationInfo.icon` both resolve to `0x7f010000`.
- Ordinary loading returns `AdaptiveIconDrawable`.
- `getDrawableForDensity(icon, 320, null)` fails inside adaptive-layer inflation
  with `Resources$NotFoundException: Resource ID #0x0`.

The generated background used an inline XML color. Density-specific loading
tries to resolve that layer's resource ID, which is zero for the inline value.
Current `linux/stubgen/.../StubGenerator.java` gives the background its own
color drawable resource (`0x7f010002`) and references it from the XML. The
resource table now has three entries. Stub version is **7**, and
`FlatpakStubManager.java` upgrades stubs older than 7.

Foreground normalization uses the 66/108 safe-area ratio. Host manifest
queries launcher activities so `MainActivity` can resolve source stub icons
for task descriptions. Launcher and window-title rendering remain unverified.
Do not assume task description icons also cover every `WindowActivity` task.

Reference: https://developer.android.com/develop/ui/compose/system/icon_design_adaptive

Earlier work sorted binary manifest attributes by Android resource IDs,
added explicit activity icons, and generated adaptive XML with foreground PNG.
The density failure explains why those earlier changes did not fix the launcher.

### Installer reports BRIDGE_APP_NOT_TRUSTED:install

Settings was already listed in `target_caller_allowlist.txt` for `install`,
and its signing certificate was registered. However,
`SystemBridgeService.knownTargets()` omitted `install` and `addons`.
Consequently `getBridgeStatus()` did not advertise them and the client
rejected the installer request locally. Current source adds those two targets;
existing package/certificate checks remain in place. The change has not been
built into a completed image or confirmed against the installer service.

### Android desktop repeatedly killed by memory pressure

r6 live `/data` uses `/dev/block/ram0`. Installing several large Flatpaks
consumed **5.7 GiB** of RAM-backed storage. Captured `MemAvailable` was about
106 MiB. `lowmemorykiller` repeatedly killed Launcher3 and the compositor as
swap was exhausted. This is separate from the wlroots abort.

Attaching an empty disk does not move live `/data` onto it. The prepared
installed disk is intended to provide disk-backed userdata without the
installer UI. Generic live boot must still work independently of this VM
workaround. A later connected VM still reported the live fstab and `ram0`;
that observation did not verify the prepared installed disk.

### Session bus output and application compatibility

Kate and Minecraft error windows displayed only:

```text
DBUS_SESSION_BUS_ADDRESS=unix:path=/data/matonos/linux/runtime/wayland-8-bus
```

This is our broker's startup output, not the application failure cause.
Current `linux/flatpak/flatpak-env-wrapper.c` redirects broker stdout to
`/dev/null`, preserving stderr. Launch status currently tracks whether the
Flatpak process is alive and reads its log; it does not retain a useful exit
code/signal. Improve diagnosis if applications still exit silently.

Steam explicitly reported `Portal call failed: The name has no owner`.
The private broker does not provide the Flatpak portal service/activation.
Do not claim Steam works after only fixing the compositor.
