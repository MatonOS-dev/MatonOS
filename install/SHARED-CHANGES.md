# Install area shared integration requests

This is a change request list only. Per the current priority instruction,
the install agent must not edit these shared files or queue a build.

## App import and authorization

- `buildinfra/apps/apps.list`: add an Expo app row for
  `matonos-installer`, project path `../../../apps/installer`, Expo build mode,
  staged APK name `MatonOSInstaller.apk`, signing key id `matonos-installer`.
- `buildinfra/Android.bp`: add a preprocessed privileged system_ext import
  for the staged installer APK and its generated package-scoped privapp XML.
- `permissions/privapp-permissions-org.matonos.installer.xml`: grant only
  `org.matonos.permission.SYSTEM_BRIDGE` and any separately justified install
  permissions. Do not grant broad package-management permissions unless the
  implementation demonstrates they are required.
- `systembridge/res/raw/target_caller_allowlist.txt`: add the exact row
  `install org.matonos.installer`; this is the only target the app needs.
- `systembridge/res/raw/caller_cert_allowlist.txt`: register only the
  SHA-256 certificate for the installer app's own key, generated by
  `tools/build-apps.sh` after the app row exists. The bridge's existing
  `SYSTEM_BRIDGE` permission gate remains unchanged; there is no live-only
  permission bypass. Security-critical authorization must continue to bind
  this channel target to the pinned installer signing certificate.

## Native service bundle

- `bundle/contents.list`: register the built `matonos-installer-service`
  executable and its init rc under `/odm/bin` and `/odm/etc/init`.
- `native/CMakeLists.txt` or the fixed native registry used by
  `tools/build-native.sh`: add the install daemon target after its NDK code is
  ready. Keep the source in `install/` until the buildinfra owner integrates
  the fixed build registry.
- `sepolicy/matonos/matonos_driver.te` and
  `sepolicy/matonos/file_contexts`: add the `matonos_installer` domain and
  binary transition, plus narrowly required raw block/partition access.
  Do not grant those write permissions to `matonos_driver`. No new policy
  files or `sepolicy/vendor/` edits.
- Add the installer instance to the existing channel VINTF manifest only if
  the service is actually registered as `vendor.matonos.channel.IChannel/install`.
- The channel API is versioned `OperationRequestV1`: `{apiVersion: 1,
  targetDiskId, operation}`. It invokes one generic primitive per call, with
  per-operation progress and cancellation. App policy/operation ordering stays
  in `apps/installer`; v3 layout/sequence policy must not require a daemon
  workflow change. Service must implement fresh enumeration and fail-closed
  safety checks immediately before each destructive primitive.

## Image and installer visibility

- `BoardConfig.mk` includes `install/BoardConfig.mk` already; no shared board
  include is needed. `device.mk` includes `install/install.mk` through its
  existing area include path only if confirmed; otherwise record the exact
  required include there before integration.
- `tools/make-live.sh`: select `_a` images only, preserve exact-fit live
  super, and pass `_a` plus `androidboot.matonos.live=1`.
- The installed first-boot package-manager/init hook must leave the
  privileged installer package disabled for every user; live boot alone
  enables it. Installer init service is disabled by default and starts only
  on live mode.
- Add an installed-image dormancy marker consumer to the first-boot hook; the
  installer app writes the marker as its final generic file operation. This
  must disable the package for every user before launcher/user interaction.
- Boot partition contract: current systemd-boot source scans one XBOOTLDR
  associated with its ESP. If keeping two physical `boot_a`/`boot_b`
  partitions, first provide a no-patch boot-manager implementation/test that
  proves both are selectable. The working contract uses one shared XBOOTLDR
  with slot-specific boot directories and is recorded in `AB-LAYOUT.md`.
