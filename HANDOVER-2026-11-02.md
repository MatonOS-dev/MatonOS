# Handover 2026-11-02: zero-copy X11 GPU path (fs-speed)

Worktree `~/matonos/repos/lsa-perf`, branch `fs-speed`, HEAD `c4dff90`.
**Everything below is uncommitted.** Goal: GLX and EGL presentation on X11 with zero copies, at ≤1.1× native.

## How the path works
1. The app renders into an Android pbuffer.
2. Each swap blits into a BGRA AHB (format 5, usage 0x100|0x200). The blit flips the image vertically for X11.
3. The AHB's dma-buf goes to Xwayland once, through DRI3 PixmapFromBuffer.
4. Each frame is shown with Present plus a fence.

AHB allocation goes through the stub compositor's `maton-ahb` unix socket in XDG_RUNTIME_DIR (`linux/subsystem/native/ahb_alloc_service.c`). This is needed because forked payloads inherit a libbinder state that does not work, so they cannot allocate directly. Direct allocation stays as a fallback.

## Changes made in this session (uncommitted)
- **Allocation service:**
  - New file `linux/subsystem/native/ahb_alloc_service.{c,h}`.
  - It is registered in `compositor_core.c` and added to the CMakeLists.
  - Supporting changes: `runtime_dir` in `bootstrap.h`, `MATON_RUNTIME_DIR` in `runtime.c`, and helpers in the arch `backend.h` files.
- **egl_vendor.c:**
  - Allocation now goes through the socket.
  - The swap and the GL delete calls use `mv_current_gl_resolve`. With a desktop GL context current, the ES trampolines jump to NULL, which crashed after a resize.
  - X11 window surfaces now accept depth-32 visuals (`mv_x11_create(...,1)`).
- **wsi_x11.c/.h:**
  - Adds a `depth` field and `visual_ok(allow_alpha)`, and creates depth-32 B8G8R8A8 pixmaps. Chrome uses ARGB windows.
  - Vulkan still uses depth 24 only (`wsi_vulkan.inc`).
- **xcb replies are now freed with the global `free`:**
  - New `mv_client_global_symbol("free")` in `wayland_resolve.c`.
  - Chrome's PartitionAlloc replaces malloc, so freeing with libc's `free` caused "free(): invalid size" and double frees.
  - The test stub was updated in `tests/wsi-x11-test.c`.
- **glx-forward/vendor.c:**
  - Window surfaces now live in one cache keyed by (Display, drawable), shared across contexts.
  - A surface is dropped only on glXDestroyWindow or when XGetWindowAttributes fails.
  - Before this, a surface was recreated every time a context switched drawables.
- **compat-proxy/proxy.c:** the crash_map refactor and the null-jump diagnostics.
- **compat-proxy/loader.c:** changes from earlier in the session.

  ```
  cd ~/matonos/repos/lsa-perf && MATON_SUBSYSTEM_OUT=$HOME/matonos/build/fs-speed-out \
    MATON_SIGNING_STORE_FILE=$HOME/.config/matonos-keys/matonos-linux-subsystem.jks \
  ```

  The "Repository corruption" line in the log is an intentional negative test.
- **Install:**
  - `adb -s localhost:5556 install -r -d --no-incremental ~/matonos/build/fs-speed-out/MatonLinuxSubsystem.apk`
  - Install the real APK, not the Bootstrap APK; the Bootstrap APK crashes with "PortalFiles class not found".
  - Wait about 20 s afterwards. The first launches may fail with "app runtime did not become ready"; retry.
- **Chrome flags:**
  - The file is `/data/data/$P/home/.var/app/com.google.Chrome/config/chrome-flags.conf`. It is currently removed.
  - If you write it as root: `chown u0_a167`, `chmod 600`, `restorecon`. A wrong MLS label stops Chrome from starting.
  - `--use-angle=gl-egl` switches ANGLE from GLX to EGL.
  - To open chrome://gpu, tap the omnibox and use `input text`. A URL in the flags file does not work.
