# Handover 2026-10-17 — v3.5 process model settled, install pipeline through PackageInstaller, GPU forwarder offscreen

## Decisions made today (all by the user)
- **v3 process model = desktop-style split.** The stub's main Android process hosts ART, the
  activities, the Wayland compositor + presenter and Xwayland (on demand). **Linux apps are plain
  native processes** under the compat proxy (`V3Launcher` → ProcessBuilder → loader): native
  `execve`, native `fork` (kernel CoW), ordinary children. When the Linux process dies, the stub's
  Android process cleans up and dies. Memory note: `v3-in-process`.
- **Dead ends (do not re-explore):** Linux apps inside the stub's ART process ("in-process v3"),
  the private AHB socket WSI transport, a direct per-window Android Surface in the Linux process.
  Code only as tags `dead-end/v3-in-process`, `dead-end/ahb-wsi-transport`; see
  linux-subsystem-app `DEAD-ENDS.md`.
- **Zero copy** everywhere; GPU frames: dma-buf → `dmabuf_import.c` wraps as AHB →
  per-surface SurfaceControl → SurfaceFlinger. `wl_shm` copy is accepted for now (candidate:
  memfd → /dev/udmabuf → dma-buf).
- **Explicit sync**, invisible to apps: sync_file fences from our ICD; `linux-drm-syncobj-v1` when
  a render node exists; `EXPORT_SYNC_FILE` bridge for implicit-only clients.
- **Emulation, not a security layer:** the Android app sandbox is the boundary; no in-process
  hardening against payloads calling into bionic.
- **GPU:** freestanding ICD (no libc, zero DT_NEEDED), architecture-portable backends; GL = Zink on
  the Vulkan forwarder unless Android EGL does desktop GL; Xwayland renders with GLES/EGL (glamor).
- **Codex budget:** sol-6.1 too expensive (≈50% budget per run); luna-6-high (≈2%) is the default
  for hard tasks with a fully specified design; sol only if luna-high fails. Free DeepSeek for
  medium tasks, one free-model job at a time. VM limits for agents are off for now.
- Old binary with a home path in the public repo's git history: leave it (user).
- `modify_ldt` stays ENOSYS (maybe emulated much later).

## Build rules learned today
- My builds of subsystem `main`: private `~/matonos/build/main-out`. Agents: own `MATON_SUBSYSTEM_OUT`;
  copy only download caches. cmake from `/mnt/data/aosp/prebuilts/cmake/linux-x86/bin`; ninja via a
  private dir containing only the ninja symlink (the AOSP build-tools dir ships an `openssl` that
  breaks the tests). Run proxy + forwarder + repo suites on the merge commit **before** pushing.
- `coord-build.sh` kills all test VMs except the user's port-5555 VM; don't start it while an agent
  needs the VM. `/data` on the live image is a RAM disk — never write big logs there.
- Never kill via pattern; literal ps-verified PIDs only, never my own shell lineage.
