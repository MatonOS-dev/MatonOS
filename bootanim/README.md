# MatonOS boot animation

The static animation and transparent composer wordmark are generated by
`generate.py` using Montserrat SemiBold under the SIL Open Font License
(`fonts/OFL.txt`). `tools/build-bundle.sh` runs the generator into the ignored
`bootanim/out/` directory before reading bundle rows. It emits
`bootanim/out/fallback.zip` and `bootanim/out/wordmark.rgba`; those generated
files are installed as `/odm/etc/bootanim/fallback.zip` and
`/odm/etc/bootanim/wordmark.rgba`. Init copies the fallback to
`/oem/media/bootanimation.zip` before starting the composer, so it remains the
no-BGRT and error fallback.

## BGRT composition

`matonos-bootlogo` runs once synchronously in init's `post-fs` action, before
init starts class `core` and the stock `bootanim` service. Init mounts a tmpfs on `/oem` itself because the image root is read-only and `/oem` is only an empty directory. It labels the mount with `restorecon`, creates `/oem/media`,
and copies the static fallback there. With a valid ACPI BGRT status bit, the
program reads the firmware BMP and offsets, chooses the first connected DRM connector's
first mode, and writes four 8 fps RGB PNG frames plus `desc.txt` as a stored ZIP.
The firmware bitmap stays at its BGRT position; the MatonOS wordmark is centered
below it, with a short moving progress segment beneath the wordmark. The new
ZIP is written beside the fallback and atomically renamed over it only after
all entries are complete. The BMP reader accepts uncompressed 24-bit and 32-bit files, including top-down images.

Stock lookup order in `frameworks/base/cmds/bootanimation/BootAnimation.cpp`
is APEX, `/product/media/bootanimation.zip`, `/oem/media/bootanimation.zip`,
then `/system/media/bootanimation.zip`. This product ships no boot animation ZIP
in the APEX or product path, so the OEM archive wins. The init-copied static
ZIP remains at that path when BGRT is absent or its valid bit is clear; the
composer logs at info level and does not modify it. Read, parse, sysfs, or write
errors are logged with path and errno where available;
partial output is removed and the fallback remains available.

SELinux gives the composer a dedicated domain. Its sysfs access is limited to
read-only BGRT and DRM mode data; the only write target is init's labeled OEM
tmpfs. The BGRT sysfs subtree has its own `sysfs_bgrt` label.

## Host test

```sh
native/matonos-bootlogo/host-test.sh /tmp/efi-logo3-host-test
```

The fixture builds the C program with the host compiler, creates fake 24-bit
bottom-up and 32-bit top-down BGRT BMPs plus a fake DRM sysfs tree, runs
composition, checks `unzip -t`, and decodes PNG
frames to verify their dimensions. It also checks that missing BGRT leaves a
pre-staged fallback unchanged, and malformed BMP data reports an error without
replacing that fallback. The normal native staging flow discovers
`native/matonos-bootlogo/CMakeLists.txt` and stages the binary at
`buildinfra/native-built/matonos-bootlogo`; `bundle/contents.list` installs it
with the wordmark and init rc.

## Build and fresh-boot checks

A full image build is needed because the service, bundle registry, file
contexts, and a new `genfs_contexts` input changed. No
AOSP source patch or kernel change is required. On a fresh image:

1. Boot OVMF with an ACPI BGRT image and a connected virtual DRM display.
2. Confirm the firmware logo remains in its reported position, MatonOS appears
   below it, and the progress segment moves until boot animation exits.
3. Confirm `/oem/media/bootanimation.zip` is selected and stored entries decode.
4. Boot with BGRT disabled and confirm the static wordmark fallback copied to
   `/oem/media` is used.
5. Repeat with no connected DRM mode and with malformed BGRT data; verify a
   loud logged error, no partial OEM ZIP, and continued boot using the fallback.

No image build or VM boot was run for this task (the task scope forbids them).
