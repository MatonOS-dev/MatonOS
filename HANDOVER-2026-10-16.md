## v3.5 (user's name for the new Linux app system)
Repo split: all subsystem code is in **MatonOS-dev/linux-subsystem-app** (public; local `~/matonos/repos/linux-subsystem-app`,
`main` = `2691952`+). The device tree pins its signed APK in `prebuilt/linux-subsystem/` (SOURCE has commit/hashes;
update steps in `linux/README.md`). Flatpak fork: MatonOS-dev/flatpak `matonos/v26.10` = `4cce363`.

Design, all user-approved today:
- App payload = OSTree packs in split APKs; index in its own split; **updates restart the app** like Android updates
  (no DONT_KILL tricks). Fixed versionCode (template), increasing revisionCode.
- **One package kind**: every Flatpak ref (app, runtime, extension) is a stub package; stubs declare other stubs as
  dependencies with mount points. Runtimes follow Flatpak: one per ref, reused across remotes, user picks when several
  remotes provide one. Unused-runtime cleanup on every install and at boot; missing runtime at launch → stub asks the
  subsystem to repair its own app.
- Remotes: store passes name/URL/key on install; recorded in the signed deployment record; updates only from that remote;
  `flathub` name reserved.
- **apply_extra** runs in each package's own service under its own UID; the package builds its own unsigned `extra_`
  split; the subsystem only checks the manifest identity (code-free, no components) and signs. Subsystem never parses
  vendor output.
- Launcher name/icon/MIME from the `.desktop` (launcher split), then appstream, then app id + generic icon.
- Delta updates: scratch repo seeded from installed packs + original commit metadata kept in the index split →
  Flathub static deltas work; per-object fallback.
- linuxd deleted; Flatpak APEX deleted (binaries + flathub.flatpakrepo in the APK); Xwayland in the APK; in-app binder
  hop and `matonos_linux_app` domain removed; bridge allowlist entry removed.
- D-Bus: **keep the C broker** (JNI in the APK); portals on our own Java wire code. No dbus-java.
- Subsystem may use START_ACTIVITIES_FROM_BACKGROUND (background installs with prompts); dataSync foreground service.

## GPU findings (spikes 1–3, branch `gpu-forward-spike`, pushed)
- In-process zero-cost forwarding is impossible: glibc and bionic both own `%fs:8` etc. Accepted: per-call FS switch.
  Host measurement: WRFSBASE switch+call 18 ns vs arch_prctl 593 ns (≈0.2–1% frame cost Vulkan/modern GL).
- Thread model that works on host: proxy traps glibc's clone → resident (bionic) `pthread_create` → glibc continues on
  that thread; fork via resident `fork()`; vfork/posix_spawn pass through; registry grows dynamically. Kernel-contract
  only (passes with glibc 2.39/2.42/2.44, musl, raw clone). Not yet run on real bionic.
- Android EGL does **not** reject `EGL_OPENGL_API`; the real limit is its 256-slot `eglGetProcAddress` table.
